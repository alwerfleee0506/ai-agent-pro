نسخة مراجعة فقط — PRO4 R2
الإصدار الظاهر: 2026.10.16-PRO4-R2-REVIEW
لم تُركب هذه النسخة على Render ولم يُعدّل المستودع أو حساب الاستضافة.
هذه نسخة مستقلة للنقاش والمراجعة قبل الاتفاق على التركيب.

الملفات
ملفات التشغيل الستة موجودة في جذر الحزمة: app.py وpro_reasoning.py وinvoice_tools.py وinvoice_ui.js وrequirements.txt وgunicorn.conf.py.
تقرير المراجعة: REVIEW_NOTES_AR.md
فروقات الكود عن PRO4 السابق: CHANGES_FROM_PRO4.patch
اختبارات التطوير داخل tests. لا حاجة لرفعها عند تركيب النسخة المتفق عليها.

التغييرات المهمة
1. رفع وتحليل حتى 3 صور، وإرسال الصور الأصلية بترتيبها إلى تعديل الصور.
   صورة واحدة: حتى 17 MB. صورتان أو 3: مجموع حتى 12 MB.
   JPEG/PNG/WebP، وكل صورة حتى 20 مليون بكسل.
   إرسال الصورة الرابعة أو خلط صور وملفات يُرفض برسالة واضحة.
   حفظ صورة شخص يحتاج صورة واحدة؛ لا تُختار صورة تلقائياً من مجموعة.
2. إعادة محاولة تهيئة قاعدة البيانات حتى 3 مرات، مع انتظار 1 ثم 2 ثانية.
   بعد الفشل تبقى الخدمة غير جاهزة وتتاح محاولة جديدة بعد 30 ثانية عبر فحص الجاهزية أو الطلب التالي.
   توجد حماية من تكرار التهيئة بالتوازي وحدود زمن لاتصال قاعدة البيانات واستعلاماتها.
3. /health يفحص جاهزية التهيئة واتصال قاعدة البيانات باستعلام فعلي؛ يرجع 503 عند الفشل.
   /live يفحص بقاء خادم التطبيق حياً فقط، ولا يعني أن قاعدة البيانات جاهزة.
4. CSP أشمل، مع nonce مختلف لكل صفحة لسكربتها، والسماح بصور data/blob/https ومعاينات الوسائط اللازمة.
   لم يُستعمل unsafe-inline لتشغيل JavaScript. تنسيق CSS الداخلي مسموح للحفاظ على الواجهة الحالية.
5. تنظيف علامات المرفقات الداخلية من سياق تخطيط البحث، مع الحفاظ على أسطر المستخدم التي بين أقواس.

الإعدادات عند الاتفاق لاحقاً
لا تحتاج متغيرات بيئة جديدة. أبقِ مفاتيح الخدمات وقاعدة البيانات وإعدادات تسجيل الدخول الحالية.
أمر التشغيل يبقى: gunicorn -c gunicorn.conf.py app:app
عامل Gunicorn واحد وخيطان كما في النسخة السابقة؛ لم تُزد العمال فتتغير أقفال الصور بين العمليات.
يمكن اختيار /health لمسار فحص الجاهزية بعد الاتفاق على التركيب، و/live للتشخيص فقط.
وجود هذه الملفات عندك لا ينشرها تلقائياً. راجعها وأرسل ملاحظاتك أولاً.

حدود التحقق
الاختبارات تستبدل قاعدة البيانات وواجهات الخدمات ببدائل محلية؛ لم تُستخدم مفاتيح حسابك ولم تُختبر الاستضافة الفعلية أو APK.
اختبار رفع الواجهة يشغّل معالج الرفع الأصلي ببدائل لعمليات المتصفح، وليس متصفحاً بصرياً حقيقياً.
تعذر تشغيل متصفح الاختبار في البيئة الحالية؛ فحص CSP تحقق من الترويسات وتطابق nonce، وليس عرضاً بصرياً مؤكداً لكل صفحة.
بعد اتفاقنا يلزم اختبار قبول قصير على الخدمة الفعلية: دخول، رفع صورتين، عرض صورة محفوظة، تصدير فاتورة، وصوت.

إضافات R2
- تنزيل الملف لا يختاره كمرفق تلقائياً. استعمل «متابعة تعديل هذا الملف» إذا أردت تعديله.
- يظهر تنبيه بالقراءتين المستقلتين عند تحويل فاتورة مصورة أو PDF من المحادثة.
- رسالة مباشرة للبحث غير المفعّل، وتجاوز استدعاءات النموذج غير اللازمة عند غياب النتائج.
- 66 تجربة Python ناجحة، مع اختبارات JavaScript الثلاثة للحسابات ورفع الصور ومتابعة الملف.
- كل نتائج التشغيل مرفقة في tests/TEST_RESULTS.txt. لم تُجرَ تجربة على Render أو الخدمات الحقيقية أو متصفح بصري.
